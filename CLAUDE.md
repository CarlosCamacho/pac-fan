# Pac-Fan — working notes for Claude

A maze-chase game for the TRS-80 Color Computer 1/2 in **Semigraphics 12** (64×96 elements,
8 colours), 6809 assembly, by Carlos A. Camacho (CAMCO). It is a fan game: never use the
Pac-Man name, Namco artwork or Namco music. The title says PAC-FAN and CAMCO; the tune is
original. The owner writes in US English: use US spelling in replies and new text.

`README.md` describes the game. This file is how to work on it.

## Build

```
LWASM=/path/to/lwasm ./build.sh      # gen.py -> tables.inc, then dist/PACFAN.BIN and .DSK
```

- **LWTOOLS 4.24 exactly** (`build.sh` checks). It is no longer packaged for Ubuntu; build it
  from source (the `stahta01/LWTools` GitHub mirror has it).
- `tables.inc` and `drawspr.inc` are **generated by gen.py**. Never edit them by hand.
- The build asserts the image ends below `$7000` (the BASIC stack sits above). At the last
  build it ended at `$6E1D`: about 480 bytes are free, roughly two more levels. Read the
  real figure from `ENDVARS` in `dist/pacfan.sym`; don't trust this line.

## Levels

- `levels/pacfan-project.json` is the owner's file from the maze editor
  (`editor/maze-editor.html`). **gen.py reads it and never writes it.** When the owner sends a
  new one, copy it over this file.
- `levels/order.json` is the **play order**, by level name. Level 1 stays first; the other
  39 were ranked easiest to hardest by the autopilot (below). A level added to the project
  must be added here too, or gen.py stops and names it.
- gen.py prints a line per level and **removes dots the player cannot reach**, warning about
  each. It also warns when the ghosts' exit is cut off from the player. As of the last
  build, no level has a warning. Dead ends are reported, but the owner uses them on
  purpose; they are not errors.
- Engine limits that gen.py enforces: 16×15 only; a house `H` with its door `D` directly
  above and an open tile above the door; one wall colour per level (per-wall colours in
  the editor are ignored); `P` = player start (else the open tile nearest the bottom
  middle).

## How the engine works (where things live in pacfan.asm)

- Screens: `BUF0` `$0E00` and `BUF1` `$1A00`, double-buffered (SAM F 7/13), flipped at field
  sync; `BG` `$2600` is the background copy. A frame restores each sprite's 3×6-byte square
  from BG and redraws it. Code from `$3200`.
- `NEWLEVEL` reads the level header (`LVTAB`, `H_*` offsets) and calls `BUILDBG`, which
  unpacks 4-bit tile types and works out wall joins (`TCODE`) exactly as gen.py does.
- Ghosts: arcade targeting (`TARGET`, `CHOOSE`, `DIST2`, which is tunnel-aware on both
  axes), scatter/chase (`MODETICK`), house and door (`E_HOUSE`; `OPEN` lets only leaving
  ghosts and eyes through the door). **Eyes go home by a per-level shortest-path map**
  (`HOMEDIR`, built by gen.py), because straight-line targeting looped under a walled-off
  house.
- Ghost speed comes from the level number in `NEWLEVEL`: 15 for levels 1–8, plus 1 every 8
  levels, 19 from 33. The player is 16.
- Death: `DEATHFLASH` cycles the walls through all 8 colours in the hidden buffer and flips
  it in (recolouring the shown buffer wiped visibly down the screen).
- Labels `LCLEAR`, `GOVER`, `MGREV`, `MGOUT`, `STWD`, `STWU` are test hooks for emulator
  traps. Keep them.

## Testing — the emulator is xroar-dev

Install it: <https://github.com/milliluk/xroar-dev>. The CoCo 2 ROMs (`bas13.rom`,
`extbas11.rom`, `disk11.rom`) are not in this repo; the owner must supply them.

```
export XROAR=/path/to/xroar-dev ROMS=/path/to/roms
tools/checkbg.sh          # every level: engine-built background == gen.py's, byte for byte
tools/botgames.sh 10      # autopilot: 10 games per level (about an hour for 40 levels)
python3 tools/rank.py     # difficulty ranking; --write rewrites levels/order.json
```

- `-DBOT=1` builds an **autopilot** into `READKEYS` (breadth-first path to the nearest dot,
  avoiding live ghosts). It is test-only and never shipped.
- xroar-dev traps: `xpc=` takes a physical address (5 hex digits). **`-trap-range N` means
  "from hit N on"; use `N-N` for a single hit.** `seconds=` is emulated time. A screenshot
  name may or may not get a digit appended, so glob for it.
- Headless runs can't be heard. Sound pitch was set from counted cycles (the sawtooth loop
  is 79 cycles, 11,328 Hz; gen.py's `SAMPCYC` must match it).
- **Nothing has run on real hardware yet.** Say so when reporting results.

## Traps already hit in this code

- `LDA B,X` is a **signed** offset: tile numbers 128–239 index backwards. Use `ABX`. (This
  hit the autopilot; the game's own `B,X` uses index tables of 21 entries or fewer.)
- `OPEN` clobbers A, B and X, so keep loop counters in memory (`CHN`), not in B. That once
  hung frightened ghosts in dead ends.
- After `ABX`, X has moved. Reload it before indexing again.
- A frequency of 0 ended the tune early, which is why records are (count, f1, f2) and a
  count of 0 ends them.

## Owner's standing rules

- **CoCoSDC support is required in every program** unless the owner says otherwise. Pac-Fan
  does no disk I/O of its own (it is `LOADM`ed), so it works from an SDC through SDC-DOS.
- Commit and push finished work to `main` on github.com/CarlosCamacho/pac-fan.
